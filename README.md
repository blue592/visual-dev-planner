# 비주얼 개발 플래너

## 프로젝트 소개

‘개발 순서 길잡이’는 기획서를 읽고 가장 중요한 기능과 가장 먼저 만들 기능을 구분하는 AI 도우미입니다. 목표는 단계별 할 일·결과물·완료 기준을 표와 도식으로 정리한 1~2장 분량의 개발 계획서를 만들고, 마크다운 파일로 제공하는 것입니다.

‘AI Agent에게 일 제대로 시키는 법 배우기’에서 이 도우미의 프롬프트를 설계하고, 영화 티어리스트 기획서로 시험했습니다.

## 주요 결과물

### 유저 프롬프트 v1~v3

| 버전 | 요청과 실제 결과 |
|---|---|
| v1 · 첫 계획서 | 예시 없이 개발 순서와 완료 기준을 요청했어요. 다섯 단계가 나왔지만 책갈피는 마지막 단계의 선택 기능으로 들어갔어요. [첫 계획서](자료/gemini.code_artifact_v1.md) |
| v2 · 책갈피 수정 | 기획서의 완성 기준에 맞춰 책갈피를 5단계 필수 기능으로 바꿨어요. 책갈피 A의 등급을 바꿔도 B의 배치가 유지되는지, 현재·전체 중 선택한 범위대로 저장되는지 확인하는 기준이 생겼어요. [수정 계획서](자료/개발계획서v2.md) |
| v3 · 첫 작업 강조 | 맨 위에 ‘지금 할 일’을 한 줄로 써 달라고 했어요. 초기 영화 카드를 등급 칸으로 옮기는 작업과 다섯 단계의 순서가 먼저 보였어요. 단계별 표 다섯 개에서는 같은 머리글이 반복됐어요. [v3 계획서](자료/v3.md) |

### 시스템 프롬프트 v1·v2

| 버전 | 지시와 실제 결과 |
|---|---|
| v1 · 페르소나 | 가장 중요한 기능과 먼저 만들 기능을 구분하도록 했어요. 첫 응답에서는 두 기능을 두 줄로 나눠 쓰고, 아래에 화살표로 개발 순서와 단계별 표 예시를 보여 줬어요. [실행 대화](docs/run-log.md#dialogue-03) |
| v2 · 문맥 끊김 보완 | 요청한 4열 표에 열이 추가된 뒤, 카드마다 직접 해 볼 동작과 화면에서 확인할 결과를 한 문장에 쓰도록 했어요. 결과에는 가로 로드맵과 카드 다섯 개가 나왔고, 3단계에는 카드를 S티어에 놓으면 그 자리에 들어간다는 완료 기준이 생겼어요. [시스템 프롬프트 개선 내용](docs/system-design.md#시스템-프롬프트-개선-내용) |
| v2 · 환각 보완 | 중복 영화가 목록에 추가된다는 잘못된 설명을 보고 기획서 원문을 따르도록 했어요. 새 이미지에서는 중복 확인 문구가 빠져, 같은 영화를 다시 넣을 때 카드 수가 유지되고 안내가 뜨는지는 확인할 수 없었어요. [시스템 프롬프트 개선 내용](docs/system-design.md#시스템-프롬프트-개선-내용) |

## 기록 기준

- 실제 사용한 프롬프트, 모델 응답과 직접 작성한 평가 원문을 보존합니다.
- AI가 제안한 점수 초안은 직접 작성한 평가와 구분합니다.
- 아직 실행하지 않았거나 확인하지 못한 항목은 비워 둡니다.
- 개인정보, API 키, 비밀번호와 계정 이메일은 공개 기록에 포함하지 않습니다.

### 제가 일하는 방식

1. **목적 먼저 파악 & 애매하면 질문**
* 기획서의 ‘목적(누가, 어떤 문제를, 어떻게 해결하는지)’부터 읽습니다.
* 목적이 흐릿하거나 핵심 목표가 여러 개라 우선순위가 갈리면, **추측해서 진행하지 않고 먼저 짧게 질문**드려요.


2. **핵심 기능 선별 (꼭 필요한 것만)**
* 목적 달성에 반드시 필요한 기능(**MVP 핵심 기능**)과 나중으로 미뤄도 되는 기능을 나눕니다.


3. **중요도 vs 개발 순서 구분**
* 가장 중요한 기능(가치/핵심)과 가장 먼저 만들어야 하는 것(기반/흐름)을 구분해서 알려드려요. (보통 핵심 기능을 돌리기 위한 뼈대·데이터·기본 화면을 먼저 만듭니다.)


4. **화살표 개발 순서 + 단계별 표**
* 전체 흐름을 `1단계 → 2단계 → 3단계` 형태의 화살표로 한눈에 보여줍니다.

### 1. 왜 ‘부가 아이디어’라고 설명했나요?

기획서 앞부분에 적힌 핵심 목적과 기본 동작을 보면, 이 앱의 본질은 “개인이 본 영화를 검색해 포스터와 함께 S~D 5단계 티어로 정리하고 관리하는 것”입니다.

9번과 10번 항목은 이런 성격을 띱니다:

* **핵심 목적과의 거리:** 이미 한 화면에서 S~D 등급 분류, 드래그 이동, 저장·불러오기가 되면 개인 영화 티어리스트의 기본 목표는 달성됩니다. 책갈피는 티어리스트를 여러 개로 나누어 관리하거나 저장 범위를 고르는 **확장·편의 기능**에 가깝습니다.


* **본문 설계와의 차이:** 기획서 본문(`1. 누가 쓰나`, `2. 무엇을 하려고`, `3. 화면과 동작`, `데이터 저장`)에서는 책갈피 생성·전환 UI나 현재 페이지/전체 페이지 저장 방식이 별도로 설계되어 있지 않고, 마지막 `5. 완성 기준`에만 추가 항목처럼 등장합니다.


* **초보자 개발 난이도:** 여러 책갈피의 독립적인 상태 관리와 저장 범위 선택까지 처음부터 같이 만들면, 기본 검색·드래그·저장 흐름을 잡는 데 시간이 더 걸릴 수 있습니다.
